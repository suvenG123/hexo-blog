================================================================================
Hexo + GitHub + Cloudflare Pages + GoDaddy 个人博客部署笔记（纯小白版）
================================================================================

写给完全不懂编程的人：
这篇笔记把每个步骤都拆碎了讲，照着抄就能搭出一个属于自己的博客。
最终效果：你在电脑上写文章 → 点一下推送 → 网页自动更新 → 别人用你的域名就能看到。

================================================================================
一、这套系统里每个软件是干嘛的（角色比喻）
================================================================================

┌──────────┬──────────────┬──────────────────────────────────────────────────┐
│ 角色      │ 软件          │ 通俗比喻                                        │
├──────────┼──────────────┼──────────────────────────────────────────────────┤
│ 🏭 工厂   │ Hexo         │ 你家的印刷厂：把你写的 Markdown 文章变成网页文件   │
│ 📦 网盘   │ GitHub       │ 带版本记录的 U 盘：存博客源码，push 就触发部署    │
│ 🚀 发射台 │ Cloudflare   │ 自动部署机器人：拉代码→构建→把网页发到全球服务器  │
│           │ Pages        │                                                  │
│ 📛 户口本 │ GoDaddy      │ 域名注册处：只卖域名和登记「谁管这个域名」         │
│ 📞 接线员 │ Cloudflare   │ 电话簿服务器：把域名翻译成IP，顺便加速和防攻击     │
│           │ DNS          │                                                  │
└──────────┴──────────────┴──────────────────────────────────────────────────┘

一句话串联：
Hexo 在本地印好网页 → 存进 GitHub 网盘 → Cloudflare Pages 自动取走发布
→ GoDaddy 告诉全世界「这个域名归 Cloudflare 管」
→ Cloudflare DNS 把访客引导到你的网页

关于 Cloudflare DNS 的额外知识（来自官方文档）：
Cloudflare 拥有全球最大的 Anycast 网络之一，DNS 查询会从离用户最近的节点响应，
延迟极低。同时自带 DDoS 防护，不怕有人恶意攻击把你网站打垮。
DNS 管理完全免费，还提供功能完整的 API 供开发者使用。

================================================================================
二、它们之间怎么连起来（架构流程）
================================================================================

你在电脑上写文章（.md 文件）
        ↓
Hexo 生成静态网页（public/ 文件夹里的 .html 文件）
        ↓
git push 推到 GitHub 仓库（比如 suvenG123/hexo-blog）
        ↓
Cloudflare Pages 检测到 push（Webhook 自动触发）
        ↓
自动执行：npm install → hexo clean → hexo generate
        ↓
把生成的 public/ 文件分发到全球 CDN 边缘节点
        ↓
用户浏览器输入 readhaven567.top
        ↓
GoDaddy 说：「这个域名的 DNS 归 Cloudflare 管」
        ↓
Cloudflare DNS 解析域名 → 指向 Pages 的边缘节点
        ↓
用户看到你的博客页面 ✅

GoDaddy 只做一件事：把域名的 NS（Name Server）改成 Cloudflare 给的两个地址。
改完之后，GoDaddy 就不再参与网页访问的流程了。

四、安装顺序与命令
================================================================================

第 1 步：安装 Node.js
  1. 去 https://nodejs.org 下载 LTS 版本（推荐 v20.x）
  2. 一路下一步安装（勾选 "Add to PATH"）
  3. 打开命令提示符验证：
     node -v
     npm -v
  4. 能看到版本号（如 v20.11.0）就说明成功

第 2 步：安装 Git
  1. 去 https://git-scm.com 下载
  2. 安装时全部默认选项，一路 Next
  3. 验证：
     git --version

第 3 步：配置 Git 用户名（第一次必做，填你自己的 GitHub 信息）
     git config --global user.name "你的GitHub用户名"
     git config --global user.email "你的GitHub邮箱"

第 4 步：安装 Hexo-CLI
     npm install -g hexo-cli
  验证：hexo -v

第 5 步：初始化博客
     D:
     mkdir hexo-blog
     cd hexo-blog
     hexo init
     npm install

第 6 步：本地预览测试
     hexo clean
     hexo generate
     hexo server
  浏览器打开 http://localhost:4000 ，能看到默认页面就说明一切正常。
  按 Ctrl+C 停止服务。

第 7 步：写第一篇文章
     hexo new "我的第一篇文章"
  文章会生成在 source/_posts/我的第一篇文章.md ，用 VS Code 打开编辑。

================================================================================
五、GitHub 配置
================================================================================

1. 登录 https://github.com
2. 点击右上角 + → New repository
3. 仓库名填：hexo-blog
4. 选 Public
5. 不要勾 Add README（重要！）
6. 点击 Create repository

本地连接 GitHub（在 D:\hexo-blog 目录下打开命令行）：
     git init
     git add .
     git commit -m "初始化Hexo博客"
     git branch -M main
     git remote add origin https://github.com/你的用户名/hexo-blog.git
     git push -u origin main

如果提示登录，按提示输入 GitHub 用户名和 Token（不是密码）。

================================================================================
六、Cloudflare Pages 配置（重点）
================================================================================

1. 登录 https://dash.cloudflare.com
2. 左侧点 Workers 和 Pages → 创建应用程序 → 选 Pages
3. 连接到 Git → 授权后选 hexo-blog 仓库
4. 构建设置填这些（一个字都别改错）：
   项目名称：hexo-blog
   生产分支：main
   框架预设：无（None）
   构建命令：npm install && hexo clean && hexo generate
   输出目录：public
   根目录：留空
5. 点击 环境变量（Environment Variables）→ 添加变量：
   变量名：NODE_VERSION
   值：20
6. 保存并部署 → 等 1-3 分钟 → 看到绿色对勾 ✅ 就成功了
7. 点击预览链接（类似 https://hexo-blog-xxx.pages.dev ）测试能不能打开

================================================================================
七、GoDaddy 改 NS
================================================================================

1. 在 Cloudflare 添加站点：输入 readhaven567.top → 选免费计划
2. Cloudflare 会给你两个 NS 地址（类似 ns1.cloudflare.com 和 ns2.cloudflare.com）
3. 登录 GoDaddy → 域名 → DNS → Nameservers → Change
4. 删掉原来的 ns63/ns64.domaincontrol.com
5. 填入 Cloudflare 给的两个 NS 地址 → Save
6. 重要：关闭 DNSSEC（GoDaddy 里找到 DNSSEC 设置 → 关闭）
7. 等状态从 Pending 变 Active（几分钟到 24 小时不等）

改完之后，GoDaddy 就不再管你的网页了，只管「这个域名归 Cloudflare 管」这件事。

================================================================================
八、绑定自定义域名
================================================================================

1. 进入 Cloudflare Pages 项目 → 自定义域 → 设置域
2. 输入 readhaven567.top → 确认
3. Cloudflare 自动添加 DNS 记录
4. 等证书签发完（状态变 Active）
5. 访问 https://readhaven567.top 测试

SSL 设置（必须做）：
左侧 SSL/TLS → 加密模式选 完全（Full）→ 开启「始终使用 HTTPS」

九、原理通俗讲解
================================================================================

★ 为什么不用 hexo d（hexo deploy）？
  因为 hexo d 是把 public 文件夹直接推到服务器。但我们走的是 Pages 自动构建，
  Pages 会自己拉源码、自己执行 hexo generate，更自动化、更可靠。

★ public 文件夹是什么？
  是 Hexo 把你写的 .md 文章「翻译」成的 .html 网页文件。
  这些 .html 才是真正给用户看的。你不需要手动管这个文件夹。

★ NS（Name Server）是什么？
  就像域名的「电话簿服务器」。GoDaddy 原本是电话簿管理员，
  你把 NS 改成 Cloudflare 后，就等于告诉全世界：
  「以后查这个域名，去问 Cloudflare 的电话簿。」

★ CDN 是什么？
  Cloudflare 在全球有很多服务器节点。你的网页会被复制存到这些节点上。
  北京用户访问时从北京节点拿网页，美国用户从美国节点拿，速度更快。

★ 为什么 push 一下网页就更新？
  因为 GitHub 和 Cloudflare Pages 之间有一个「Webhook」（自动通知机制）。
  你一 push，GitHub 就拍一下 Cloudflare 的肩膀说「有新代码了」，
  Cloudflare 就自动拉代码、重新构建、更新网页。

十、常见踩坑（必须列全，照着避坑）
================================================================================

1. theme: 后面没空格
   ✗ theme:ayer    ✓ theme: ayer
   没空格会导致整个配置文件解析失败

2. 文章没写 --- Front-matter 导致 js-yaml 报错
   每篇文章顶部必须有：
   ---
   title: 文章标题
   date: 2026-10-13 10:00:00
   tags: [标签]
   categories: 分类
   ---
   少了这个，Hexo 直接跳过渲染，本地 Cannot GET /

3. Cloudflare 默认 Node 版本低 → 必须加 NODE_VERSION=20
   不设这个变量，构建可能绿了但网页空白

4. 构建命令没写 npm install → 依赖没装
   构建命令必须是：npm install && hexo clean && hexo generate

5. GitHub Desktop 只 Commit 没 Push
   Commit 只是存到本地，必须再点 Push origin 才推到云端

6. 换主题白屏：主题名大小写不对 / 缺渲染器依赖
   theme: next 必须和 themes/next 文件夹名完全一致

7. Ayer 主题 PJAX 与 Rocket Loader 冲突
   Ayer 的动画特效和 Cloudflare 的 Rocket Loader 打架 → 白屏
   解决：速度 → 优化 → 关闭 Rocket Loader

8. 网页空白先查本地 hexo s
   本地都看不到，就别折腾线上。先解决本地问题。

9. 浏览器缓存误判 → Ctrl+F5 / Purge Everything
   改了东西网页没变，先强刷。不行就去 Cloudflare 清缓存。

10. GoDaddy 没关 DNSSEC 导致证书签发慢
    改 NS 前必须关 DNSSEC，否则 SSL 证书可能卡几小时

11. 域名绑到 Worker 而不是 Pages → ERR_CONNECTION_CLOSED
    在 Pages 里绑自定义域，不是在 Worker 里绑

12. PowerShell 不支持 && 符号
    旧版 PowerShell 里要分三行运行：
    hexo clean
    hexo generate
    hexo server

13. 文件名带 .md.md 双后缀
    用 hexo new 生成文章时别手动加 .md，否则生成 xxx.md.md

14. 副本文件冲突
    source/_posts 里不能有「xxx - 副本.md」，会导致重复渲染

十一、日常发布流程
================================================================================

以后每次写新文章，就按这个流程：

1. 打开命令行，进入博客目录：
     cd D:\hexo-blog

2. 新建文章：
     hexo new "文章标题"

3. 用 VS Code 打开 source/_posts/文章标题.md 写内容
   （注意顶部 --- 格式别写错）

4. 本地预览（可选但推荐）：
     hexo clean
     hexo generate
     hexo server
   浏览器打开 http://localhost:4000 看看效果
   按 Ctrl+C 停止

5. 提交并推送（二选一）：
   方式 A - 命令行：
     git add .
     git commit -m "新文章：文章标题"
     git push
   方式 B - GitHub Desktop：
     打开 GitHub Desktop → 勾选更改的文件
     Summary 填「新文章：文章标题」
     点 Commit to main → 点 Push origin

6. 等 1-3 分钟 → Cloudflare 自动部署变绿

7. 刷新网页 → 按 Ctrl+F5 强刷 → 看到新文章 ✅
